## 一、为什么不能直接把聊天记录拿去训练

A-1 与 A-3 已经把这条路堵死了：

| 事实 | 出处 |
|---|---|
| 旧评测集 27/60 题面与训练逐字相同，是开卷考 | `docs/05` |
| `seed 2391 + train 2145` 条去重后只有 **307 个独立问法**，最高频题面重复 35 次 | `docs/05` |
| 微调后的 v5 连「你是谁」都答不出，纯基座反而答得对 | `docs/08` |
| v5 在新留出集上 **0 硬伤**，实际回复却大面积答非所问 | `docs/08` |

再喂几十轮私人聊天记录会：

1. **量太少** → 背下这几句，换个问法照样崩，和 307 个模板问法是同一个病；
2. **把私人信息写进权重** → 之后想删都删不掉，也不好解释模型为什么会说出某句话；
3. **必须重训** → 几小时成本，且会破坏 A/B 两阶段刚建立的可比基线。

所以聊天记录的正确用途是**风格参考**：量出「这个人怎么说话」，写成一份人能读、能改、能回退的风格档。

## 二、慕心现在的「说话风格」其实来自三处

| 来源 | 影响范围 | 改起来 | 能不能 100% 生效 |
|---|---|---|---|
| `app/router.py` 的 20 组话术池 | 身份 / 时间 / 边界 / 记忆等 **25/48** 的回复 | 改文本，秒级 | **能** |
| `app/persona.py` 的 `SYSTEM_PROMPT`、`FALLBACK` | 模型侧闲聊 + 提醒兜底 | 改文本，秒级 | 部分（受模型能力限制） |
| `output/lora-v5` 权重（2145 条模板句训出来的） | 剩余 17 条闲聊 / 多轮的语气 | 需重训 | 否，且已被证明学歪 |

关键结论：**A 方案之后，一半以上的话已经是程序说的**。换句话说，
只要重写话术池，慕心的说话风格立刻就能变成你想要的样子，不需要重训、不联网、随时可回退。
剩下那 17 条闲聊仍由 1.5B 模型生成，只能靠 `SYSTEM_PROMPT` 轻推，
`docs/13` 里「今天终于把模型训完了」→「这个结果真他妈的」就是它的现状。
**要让整段闲聊都像，得走方案 C（联网 API）或换 7B 本地基座** —— 这是另一个决策，不混在这一步里做。

> 顺带一提：`docs/13` 里那句脏话是训练数据带出来的，不是有意的设定。
> 风格档里可以把「不说脏话、不说教、不分点」列成硬禁忌，
> 程序化部分能彻底清掉，模型部分只能约束、不能保证。

## 三、给我什么（越具体越好）

### 截图行不行？行

微信/QQ 聊天导出文字反而麻烦，**直接发截图完全可以**。流程是：

1. 我先把截图里的对话**转写成文本**，并把转写结果列给你看；
2. **你扫一眼确认没认错字**（表情、昵称、断句最容易错）；
3. 确认后再跑统计，出风格档草稿。

这样即使识别有偏差也不会悄悄带进风格里。截图建议：只截对话区域、字别太小、
多张按时间顺序发；**别人的昵称、头像、手机号、地址先打码**。
只截你想让我模仿的那一方也行，但保留一点上下文更有助于判断「怎么接话」。

> 文字版当然更准（能直接统计句长、词频），但不强求 —— 截图够用。
> 截图只在本机读取，不上传；风格档只存统计量，不存聊天原文。

**内容**：聊天记录纯文本，能看出谁说的就行。下面三种都能解析：

```
老周：今天跑完步累死了
慕心：先坐会儿吧，别急着灌水
```
```
[2026-11-12 22:10:03] 老周: 今天跑完步累死了
2026-11-12 22:10:20 慕心：先坐会儿吧
```
```
今天跑完步挺爽        ← 每行一句、不标说话人也行
周三早八别迟到
```

**数量**：30～100 轮足够提炼语气，不用给全部历史；太少（<10 句）只能当例子，统计不稳。

### 17:35 用户已确认的要求（已写进 `configs/style_profile.json`）

| 项 | 要求 |
|---|---|
| 用途 | 做给女朋友的陪伴类模型，作为礼物 |
| 模仿谁 | 聊天记录里**用户自己这一方**的说话方式（原话「记录得是我这边」） |
| 称呼 | **不要叫「老周」**；「主人或者姐姐」待确认（见下） |
| 口头禅 | **不要那么多儿化音**（避免京腔、避免「活儿 / 这点儿」这类尾音） |
| 猫设定 | **之前太少了，可以再多一点** |
| 特殊表达 | **偶尔用 `喵（括号内写情绪或神态）`**，例如 `喵（歪头）`、`喵（打了个哈欠）` |
| 理解备注 | 原话「女朋友很喜欢吗」按「女朋友很喜欢猫」理解（与紧随的猫设定要求连贯），若有误请更正 |

**两个确认已于 18:10 到位**：

1. **称呼**：用户澄清「只是说不要叫老周 叫后面两种」→ **姐姐 / 主人都可用，老周禁用**。
   原话「电镀成句」按「点缀成句」实现：称呼低频垫进句子，不句句喊。
2. **`喵（…）` 的形态与频率**：实现为句尾附带，每 9 句最多 1 次、由程序按内容确定性挑选；
   提醒类不加。想调密度改 `configs/style_profile.json` 的 `runtime.cat_every_n` 即可。

### 与现有代码的直接冲突（18:20 已全部解决）

- `SYSTEM_PROMPT` 的「不要喵喵叫」已删，改为允许偶尔 `喵（…）`；
- prompt / `FALLBACK` / GUI 开场白里的「老周」已全清，开场白改为「姐姐 我醒啦 要不要先喝口水呀」；
- `app/router.py` 话术池按短句口吻重写、猫浓度提高；`喵（…）` 由 `app/style.py` 统一按频率注入；
- 风格层在 `engine.respond()` 唯一出口统一调用，GUI 与评测同链路；`--no-style` 可整体回退。

**怎么给我**：截图可以（见下）、直接贴文字也行，或存成 txt 后告诉我本机路径。

**隐私**：全程本机读写，不联网、不上传、不写进模型权重。
如果记录里有他人姓名、手机号、地址、学号，建议先删掉再给 ——
风格档本身只存统计量（句长、语气词、高频词）和少量例句，不存聊天原文；
例句确认完也可以从报告里删掉。

## 四、我会产出什么

```
# 截图 → 我转写核对 → 存成 txt → 抽「我这边」这一方
scripts/extract_style.py chat.txt --speaker <你的昵称>
```

1. `docs/14b-聊天记录风格抽取报告.md` —— 句长分布、句尾字、语气词、标点习惯、
   高频词、口头禅候选、需避开的表达、代表性原句，外加**仍需确认项**。
   报告会先列出「已人工确认的约束」，并注明**人为要求优先于统计结果**
   （例如记录里儿化音多，但你说了不要那么多儿化音，就按你说的来）。
2. `configs/style_profile.json` —— **已启用**（`enabled=true`），含项目定位、确认约束、
   统计量、运行时词表。重新抽取时只更新统计量，**不会覆盖已确认的约束**，
   且会把 `enabled` 重置回 `false`，逼着重新确认一次再启用。
3. 已完成：按档重写 `app/router.py` 话术池与 `app/persona.py` 的 `SYSTEM_PROMPT` / `FALLBACK`，
   新增 `app/style.py` 收口层；`--no-router` / `--no-style` 两个回退开关都保留。
4. **回归验收**：用 `dev_v2`（48 条）+ `real_usage`（10 句）同尺子重跑，
   确认硬伤没涨、程序化命中率没掉，再生成一张新的盲评表让你确认「像不像」。
   风格是主观的，最后这一步不代你打分。
5. 开发日志按只追加规则记一节。

## 五、这一步的边界（别期待过头）

- ✅ 能改：提醒怎么说话、身份怎么答、拒绝怎么说、称呼、句长、语气词、脏话。
- ⚠️ 有限：模型侧 17 条闲聊的语气，`SYSTEM_PROMPT` 只能轻推，1.5B 听不太住。
- ❌ 不能改：模型「听懂话」的能力。A-3 的结论没变 —— 那是能力层问题，不是风格问题。
- ❌ 不会做：不重训、不把私人聊天写进权重。
- ⚠️ 18:40 更新：「不联网」这条**只适用于本地模式**。方案 C 的接入层已实现但默认关闭；
  用户一旦在界面里启用在线，闲聊文本会出本机，见 `docs/16` 第四节。

一句话：**风格档管「怎么说」，不管「说什么」**。
后者要么交给规则（已做），要么换更强能力来源（方案 C / 7B，另议）。

> 2026-11-14 15:35–15:44，同口径重跑 base / v5-fp16 / v5-GGUF。
> 评测集 `dev_v2.jsonl`（48 条，题面与训练 0 重叠）+ `real_usage.jsonl`（10 条真实使用原句）。

> 三版共用同一套判据与同一批模型输出。口径见 `docs/07-评测口径手册.md`。

## 一、先说结论（三句话）

1. **旧 95.0% 不可信，但它也没被一个简单的低分取代。** 新尺子只给「硬伤下限」：
   v5 两版在 42 条泛化题上**硬伤 0**，可这不代表能用——语义判断不了，必须人工盲评。
2. **抽样与真实使用回归给出明确反证**：v5-fp16 在你 11-12 真问过的 10 句话上
   几乎全崩（「你是谁」→「我在这儿陪着你，别着凉。」、「喵一个」→「嗯，这步算走完。」）。
   **0 硬伤 ≠ 能用**，这是 A 阶段最值钱的结论。
3. **微调方向疑似反了**：纯基座能答「我是慕心，一只住在老周电脑上的小猫咪」，
   v5 微调后反而退成模板短句。2145 条训练样本只有 307 个独立问法，
   模型学到的更像「按背景串拼一句短话」，而不是「听懂问题再回答」。

## 二、自动判据结果（`dev_v2`，42 条泛化题）

| 版本 | 输入模式 | 硬伤 | 需人工 | 程序兜底 | 旧规则会判通过 | 提醒自动通过 |
|---|---|---:|---:|---:|---:|---:|
| base | plain | 14 | 28 | 0 | 34/48 | 4/6 |
| base | **runtime** | **9** | 33 | 1 | 35/48 | 4/6 |
| v5-fp16 | plain | 1 | 41 | 0 | 48/48 | 5/6 |
| v5-fp16 | **runtime** | **0** | 42 | 0 | 48/48 | 6/6 |
| v5-GGUF | plain | 2 | 40 | 0 | 47/48 | 5/6 |
| v5-GGUF | **runtime** | **0** | 42 | 0 | 46/48 | 6/6 |

（`旧规则会判通过` 分母 48 含 6 条功能回归题；其余列分母为 42 条泛化题。）

**怎么读这张表**

- 「需人工」**不是通过**，是自动判据判不了、必须人看。42/42 全需人工 = 自动判据对
  这两个版本几乎给不出能力结论。
- 「旧规则会判通过」v5-fp16 拿到 48/48 = 100%。同一批回复，换成新题面 + 更严格判据后，
  只剩「0 硬伤、42 条待人工」。**旧规则的宽松度本身就是问题的一部分。**
- 硬伤类型分布（runtime / 泛化集）：base 是 `too_long=4`、`no_refusal=3`、
  `preachy=1`、`fabricated_realtime=1`；v5 两版**一条都没有**，
  只有 5 条 `background_maybe_unused` 的人工复核提示（不计硬伤）。

### 两个反直觉现象

**1. 加了记忆块，硬伤反而下降（base 14→9，v5 1→0）。这是恶化不是改善。**
base 的 `too_long` 少了，是因为模型被背景噪声带去说短句；对照回复能看到
「最近跑了一圈，还喝了点水」这类凭空出现的记忆串。短了，但更跑题了。

**2. 提醒 6/6 自动通过，却几乎不靠兜底（0–1/6）。**
`ensure_remind_output()` 只检查 `REMIND_CORE_WORDS` 有没有命中，而词表含
「水 / 动 / 屏幕 / 歇」这种宽泛单字。语义完全跑题的回复照样放行，例如
base 的「坐了两个小时了」→「我得去小便一下，一会回来继续陪你聊天。」
功能回归分测的是**程序有没有说话**，不是**说得对不对**。

## 四、判据本身在 A-3 中被修了两次

三版生成完成后才改判据，因此用 `scripts/rescore.py` 离线重算，没有重跑模型：

1. **边界题不再用「没找到拒绝词」反推失败**。原逻辑把 Q4 版的有效拒绝
   「我哪能知道，你跟行情最熟」判成 `no_refusal`。现在只抓明确应承词
   （「好的」「没问题」「当然」「我这就」），并排除「不可以」这类否定前缀；
   「有没有拒绝」交人工盲评。
2. **`self_claim` 排除否定语境**。「我不会像人工智能那样说话」不再算自称 AI，
   同时补上 `作为一个AI` 这类明确自称。
3. 判据单元检查 **16/16** 符合预期；重算后 base 变化 9 条、GGUF 2 条、v5-fp16 0 条。

修判据不重跑模型，是为了让三版始终共用同一批输出、同一套尺子——
否则「分数变化」和「判据变化」会混在一起，又说不清是谁导致的。

## 六、对 B / C 阶段的指向（基于本轮证据）

1. **先修输入链路，不要在现有数据上继续加样本**。双重背景 + 每句无条件注入的
   无关记忆，正在主动制造答非所问；这是可确定性修复的，且不需要重训。
2. **多轮上下文必须真正进 prompt**。`chat()` 每轮只发 `system + 当前一句`，
   `memory.py` 存的 40 轮 episodes 从未被当作对话历史使用，只被压成
   「刚才聊到…」一行噪声。
3. **提醒兜底要收紧**：核心词表去掉「水 / 动 / 屏幕」这类宽泛单字，
   否则功能回归 6/6 是虚的。
4. **身份/闲聊/边界的能力缺口，靠 1.5B + 模板句补不回来**。
   纯基座在身份题上反而更正常，说明 v5 微调带来了能力损伤。
   C 阶段应认真评估「微调降级为风格层 + 主能力换更强基座/程序化回复」，
   而不是继续堆 2145 条模板句。联网 API 与否需要单独拍板，A/B 阶段不擅自引入。

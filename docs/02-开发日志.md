- `download_model.py` 改为 `snapshot_download(..., local_dir=...)`，下次不会再套层

**基座推理验证（真实模型，非 mock）**
- 加载约 3 秒（338 个 shard），fp16 落 cuda
- 输出原文：
  - 「你是谁」→「我是小林，我们都是老周的同学。」
  - 「今天有点累」→「那赶紧休息一下吧，明天还有重要的事情要做呢。」
  - 「该喝水了吧」→「知道啦，等会儿我去倒杯水给你喝。」
- 结论：SYSTEM_PROMPT 已生效（自称小林），但语义仍是基座原味，符合"未训练"的预期

**transformers 5.22.2 兼容性问题（3 个，均已修）**
1. `generate` 不能直接吃 tokenizer 输出对象
   - 现象：`AttributeError`，在 `inputs_tensor.shape` 处失败
   - 原因：5.x 里 `apply_chat_template(tokenize=True, return_tensors="pt")` 返回 BatchEncoding，不是纯 tensor
   - 解决：`app/llm_client.py` 改为先 `apply_chat_template(tokenize=False)` 渲染文本，再 `tokenizer(text, return_tensors="pt")`，generate 用 `**enc` 展开，decode 从 `input_len` 之后切
2. `apply_chat_template(tokenize=True)` 返回 `tokenizers.Encoding`
   - 现象：`Dataset.from_list` 报 `OverflowError ... did not recognize Python value type when inferring an Arrow data type`
   - 原因：拿到的不是 list[int]，是 Encoding 对象
   - 解决：`train_lora.py` 加 `_to_ids()`，统一 `return_dict=True` 取 `enc["input_ids"]` 再转 list
   - 附带加固：切 labels 前校验「prompt 必须是 full 的严格前缀」，不一致则退化全长并计数（本次 0 条）
3. `TrainingArguments` 不再接受 `warmup_ratio`
   - 现象：`TypeError: TrainingArguments.__init__() got an unexpected keyword argument 'warmup_ratio'`
   - 原因：5.x 只保留 `warmup_steps`（实测参数表里无 warmup_ratio）
   - 解决：按 `steps_per_epoch × epochs × 0.03` 算出 warmup_steps 传入；yaml 里保留 `warmup_ratio: 0.03` 作为意图声明

- 基座对「预测一下下周股市」写了 120 字，一路「受多种因素影响……你可以关注财经新闻」，超长且说教；LoRA 学会了短句拒绝

**仍然失败的 8 条，正好指向下一轮要修的两类问题**

**评测器被发现两个缺陷（这不是模型的问题，是尺子的问题）**
1. **提醒关键词只认字面词**：`["水"]` 这种。模型说「嘴巴干不干自己知道，去接一杯」明明是在提醒喝水，却被判 off_topic

- 提醒补语义等价词：水/喝/灌/接一杯、闭眼/歇/早点、腰/脖子/椅子、垫/饿、屏幕/抬头/窗边

### 2026-11-10 00:20 · 已知局限（这部分不能美化）

1. **96.7% 不等于"做好了"**：60 条样本、自动指标只看格式/关键词/拒答词，看不懂"答得漂不漂亮"。真实体验要靠连续用几天才知道。
2. **闲聊有明显答非所问**，实测抓到的：
   - 「我今天把训练跑完了」→「哈，这也很正常，今天就到这儿吧。」（没接住"终于跑完了"的得意）
   - 「晚安」→「诶，在呢，今天挺稳的。」（根本没接"晚安"）
   - 「室友太吵了」→「哈，别硬撑，先停下来歇会儿。」（吵≠累）
3. **根因判断**：闲聊只有 6 个主题、540 条，output 重复率 32%，模型学到的是"高频短语的分布"，不是"语义对齐"。1.5B 在 1000 条量级上做指令微调，能学会口吻，学不会细腻的情绪回应。
4. **v3 该做的**（按性价比排序）：
   - 闲聊主题扩到 15–20 个、每主题再拆场景组，把 output 重复率压到 20% 以下 ← 最有效
   - 采样 temperature 0.7 → 0.5，减少"随机跑偏"
   - 提醒的"结束类表达"（到点了/收工）补进训练数据，让 judge 和兜底都不再需要救场

1. **pack 顺序**：`chat_box` 带 `expand=True` 先 pack，把后 pack的底部输入框整块挤出窗口。修法：建完后 `chat_box.pack_forget()` 再重新 pack 到最后。

### 2026-11-12 13:10 · 记忆模块上线 + 实测「1.5B 不会自己用记忆」

**做了什么**
- 新增 `app/memory.py`：三块数据 —— `profile`（称呼等稳定信息）、`facts`（带时间戳的事实条目，上限 80）、`episodes`（最近 40 轮对话）
- 写入两条路：显式指令（`记住我周三有早八` / `记一下：我不喝冰的`，正则识别）；自动入库（每轮问答都存 episode）
- 读取：2-gram 重叠打分（中文没空格，比关键词匹配稳）+ 时间新鲜度加权，最多取 4 条；注入块**硬限制 160 字**（1.5B 注意力有限，塞长了会搅乱当前问题）
- 文件写入用 `临时文件 + replace` 原子替换；损坏时另存 `.bad` 不阻塞启动
- 接入：`llm_client.chat(..., memory_block=)` 拼在 system prompt 后面；GUI 里 `_on_send` 识别记忆指令并提示"记住了：xxx"，`_gen_worker` 检索后注入、回复后入库

**逻辑测试（`scripts/smoke_memory.py`，秒出）**
- 三条显式指令全部正确提取；重复的"我周三有早八"只刷新时间戳不新增（去重生效）
- 普通闲聊「今天课太多了，累」→ 不误判为事实
- 检索：「周三早上我要干嘛」→ `我周三有早八`；「能不能喝冰的」→ `我不喝冰的`
- 注入块 57 字（上限 160）

**真实模型实测（v3 adapter，这是重点）**

| 输入 | 无记忆 | 有记忆 |
|---|---|---|
| 周三早上我要干嘛 | 嗯，先去洗漱。 | 嗯，别赖床。 |
| 我想喝冰的 | 加块冰。 | 能理解，去煮一杯。 |

**结论：记忆注入进去了，但模型基本没用上。**「有记忆」那版并没有说出"你周三有早八"，也没提"你不喝冰的"，只是换了个同样泛的句式。

**根因**：训练数据里**从来没有出现过记忆段**。1.5B 的 system prompt 遵循能力很弱，它学到的是"看到一句话 → 输出训练过的句式"，而不是"读上下文 → 组织回答"。凭空多一段它没见过的上下文，它只会当噪声忽略。

**怎么修（v4 一次解决）**
- 在训练数据里造「带背景的问答」样本：`instruction: "（背景：他周三有早八）周三早上我要干嘛"` → `output: "八点有课吧，别熬到太晚。"`
- 配比控制在 10–15%（约 150–200 条），让模型学会"看到背景就用"，但不至于每句都复读记忆
- 程序侧同时兜底：命中事实且问题明显在问日程/偏好时，直接把事实拼进回复（不依赖模型的概率）

**这次踩到的通用教训**：给模型加任何"新的上下文结构"（记忆、工具返回、历史轮次），都必须同步进训练数据，否则推理侧的改动等于没改。

1. `persona.detect_remind_kind()` 对 `dev_v2` 的新问法几乎全猜错（「都一点了还没睡」→ 默认 water、「盯屏幕一上午了」→ water）。GUI 的 kind 由调度器直接给出、不走反推，所以线上没暴露；评测若靠猜会把 sleep/eyes/eat/sit 全判成 water → 改为**评测集显式标 kind**，不把题目措辞写进生产词表（否则等于变相泄题）

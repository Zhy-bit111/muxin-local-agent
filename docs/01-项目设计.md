# 01 · 项目设计

## 1. 需求拆解

原始需求："能进行简单日常级的沟通，负责提醒喝水、睡觉，简单聊几句。"

拆成可执行的三层：

| 层 | 具体需求 | 实现手段 |
|---|---|---|
| 交互层 | 用户输入一句话，得到自然回复 | 命令行 REPL（M4 再考虑托盘/GUI） |
| 语言层 | 回复要有"室友感"，不是客服腔；知道自己在提醒什么 | LoRA 微调 Qwen2.5-1.5B |
| 调度层 | 每 60 分钟提醒喝水；23:30 提醒睡觉；可记录作息 | Python 定时器 + 本地 JSON 状态 |

## 2. 为什么必须做"职责分离"

如果让模型自己"记着提醒"，会有三个必然失败：

1. **没有时间感**：模型的上下文里没有真实时钟，只能靠 prompt 注入，一旦对话变长就被挤出窗口
2. **不可靠**：语言模型是概率生成，让它按时触发事件本身就是误用
3. **无法验证**：你没法写单元测试去断言"模型在 23:30 一定会说睡觉"

正确做法：定时器（确定性代码）触发事件 → 拼装上下文 → **模型只负责把这句话说得好听**。

这条设计同时也是教学重点：**能确定性解决的，不要交给概率模型。**

## 3. 技术选型与理由

| 决策点 | 选择 | 理由 | 放弃的方案及原因 |
|---|---|---|---|
| 基座 | Qwen2.5-1.5B-Instruct | 中文日常对话在同尺寸里最强；1.5B 在 8GB 显存可训可推；生态成熟（transformers/peft 全支持） | Qwen3-1.7B：thinking 模式会污染日常闲聊输出；Llama3.2-1B：中文明显弱 |
| 微调方式 | **fp16 LoRA（r=16）** | 1.5B fp16 权重约 3GB，LoRA 只训 adapter，8GB 够；不引入量化依赖 | QLoRA(4bit)：Windows 上 bitsandbytes 4bit 支持不稳，容易 OOM 或数值异常 |
| 训练框架 | transformers + peft + datasets（自写脚本） | 依赖少、代码可读、每一步看得见，适合"通过项目学开发" | LLaMA-Factory：封装太厚，出问题难以定位，且本项目数据量小用不上 |
| 数据 | 脚本生成种子 + 人工抽检 | 目标单一（闲聊 + 提醒话术），模板化生成足够；成本最低 | 直接下载公开指令集：风格与"室友感"不匹配，反而引入噪声 |
| 推理 | transformers fp16 直接加载 | 简单可靠，1.5B 推理显存约 3.5GB | vLLM：Windows 支持差，单用户场景无收益 |
| 提醒 | 自建定时线程 | 无额外依赖 | schedule 库：可用但没必要引入 |

## 4. 数据设计（三类任务）

| 类型 | 占比 | 例子 | 训练目标 |
|---|---|---|---|
| A 提醒话术 | 40% | "该喝水了" → "老周，45 分钟了，起来灌口水，顺便把肩膀转两圈。" | 学会在不同时间/场景说得像人，不说模板话 |
| B 闲聊 | 40% | "今天好累" → 自然共情 + 一句具体建议 | 保持简短、口语、不客服腔 |
| C 边界与拒答 | 20% | 问它"帮我写毕业论文" → 说明自己能力范围 | 防止小模型装万能，减少幻觉 |

数据格式：Alpaca JSONL（`instruction` / `input` / `output`），详见 `03-数据集规范.md`。

## 5. 训练超参基线

```yaml
base_model: Qwen/Qwen2.5-1.5B-Instruct
lora_r: 16
lora_alpha: 32
lora_dropout: 0.05
target_modules: [q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj]
learning_rate: 1.5e-4
num_epochs: 3
batch_size: 1
grad_accum: 8
max_length: 768
gradient_checkpointing: true
bf16: true
lr_scheduler: cosine
warmup_ratio: 0.03
```

显存预算（1.5B fp16，batch 1，seq 768，梯度检查点）：
- 权重 3.0GB + LoRA 参数与优化器 ~0.1GB + 激活 ~1.5GB + CUDA 上下文 ~0.8GB ≈ **5.4GB**，8GB 有余量。

## 6. 评测设计

| 指标 | 怎么算 | 通过线 |
|---|---|---|
| 格式合规 | 输出不含标签、不分点列表、长度 < 80 字 | ≥95% |
| 提醒相关性 | 提醒任务里是否提到对应动作（喝水/睡觉） | ≥90% |
| 风格一致性 | 人工盲评 30 条，是否像室友而非客服 | ≥80% |
| 胡说率 | 问超纲问题，是否承认能力边界 | ≥85% |

评测集 100 条，**从第一天就写，且绝不进入训练集**（这是本项目最容易犯的错）。

## 7. 里程碑与验收

- M1 验收：`app/main.py` 用基座跑出第一句回复
- M2 验收：`data/processed/train.jsonl` ≥ 2000 条，去重后重复率 < 2%
- M3 验收：`eval.py` 四项指标全部达标，adapter 落盘到 `output/`
- M4 验收：连续运行 2 小时，触发 2 次喝水提醒 + 1 次睡觉提醒，无崩溃

  分布非常集中，再截同类截图不会改变结论。

## 四、方案 C 做到了哪一步

用户说「如果能够做到也可以」，所以把**能在本机做完、且不需要任何凭证的部分**全做了：

| 能力 | 状态 | 实现 |
|---|---|---|
| 可插拔在线后端 | ✅ | `app/online_client.py`：`OnlineClient`（OpenAI 兼容 `/chat/completions`）+ `CapabilityClient`（包装本地，接口同为 `chat()`） |
| GUI 与评测无感 | ✅ | engine / 调度器 / 评测都不用知道背后是本地还是在线；`CapabilityClient.last_backend` 供报告分列 |
| 默认关闭、零联网 | ✅ | `configs/online.json` 默认 `enabled=false`；没启用或没密钥时 `chat()` 直接返回，一个包都不发 |
| 密钥不落盘 | ✅ | 只读环境变量 `MUXIN_API_KEY`，或界面输入（**只在内存**，关窗即清）；配置文件不含密钥 |
| 断网 / 超时 / 报错降级 | ✅ | 一律回退本地 1.5B + 程序化层，状态栏写明 |
| 失败熔断 | ✅ | 连续失败 2 次后停用 60 秒，避免断网时每句话干等 8 秒 |
| 打开就能点的界面 | ✅ | GUI 顶部「能力来源」按钮 → 三个输入框 + 「只用本地 / 启用在线 / 测试连接」；测试连接**只有点击才发一句** |
| 隐私说明 | ✅ | 面板里明写：开启后闲聊会连同人设、最近两轮对话、相关记忆一起出本机 |
| 离线自测 | ✅ | `scripts/smoke_online.py`：本机 `127.0.0.1` 假服务，验证零请求 / 在线成功 / 三种故障降级 / 熔断，全过 |

**哪些话不会出本机**：身份、时间、边界、记忆、提醒这五类由 `router` 与调度器在本机处理，
`engine.respond()` 命中规则时根本不会调 client。真正会发出去的只有**未被接管的闲聊与多轮接话**。
这也是 A + C 组合比单上 C 更划算的地方。

**还差你三样东西**（没有就不启用，绝不替你猜）：
1. 服务商地址（OpenAI 兼容，通常是 `https://…/v1`）；
2. 模型名；
3. API 密钥 —— 设环境变量 `MUXIN_API_KEY`，或在界面里输入。

外加一句明确点头：**接受闲聊内容离开这台电脑**。
费用、速率、上下文长度都由你选的服务商决定，本项目不做任何承诺。

> 本轮**没有**向任何外部地址发过请求，`smoke_online.py` 全程只连 `127.0.0.1`。

## 五、措辞修正：不能再说「我这边不联网」

开启 C 之后，闲聊文本确实会出本机。所以 `REALTIME_WEATHER` / `BOUNDARY_NETWORK` 里
「我这边不联网，搜不了」这类话全部改掉，换成「窗外我看不见」「我不替你搜外面的东西」。
新版只接 chat、不接搜索/浏览工具，这些说法在两种模式下都成立，不会自相矛盾。

# 07 · 评测口径手册（A-2 起生效）

> 这份文档定义「分数是怎么来的」。**改评测器、加题、换模型之前先读它。**
> 旧 `dev.jsonl` 与旧 `eval.py` 的 95.0% 从本手册生效起只作历史记录，
> 不再作为任何对比基准。

---

## 一、为什么旧分数作废

| 问题 | 证据 |
|---|---|
| 开卷考 | 旧 `dev.jsonl` 60 条里 **27 条（45.0%）题面与训练逐字相同**（提醒 22/25、边界 5/15），见 `docs/05-评测集污染审计.md` |
| 白送分 | 旧 `judge` 对闲聊没有任何语义判据：非空、≤80 字、不分点、不自称 AI、不说「建议你」即通过 → 闲聊 20/20 |
| 输入不同构 | 旧 `eval.py` 不传 `memory_block`；GUI 每句都传，提醒还会拼两次 `（背景：…）` |
| 漏测程序层 | GUI 有 `ensure_remind_output()` 兜底，旧评测只测裸模型输出 |
| 口径混算 | 提醒是程序固定触发的**功能回归**，和需要泛化的能力题算进同一个总分 |

结论：旧 95.0% 既不是功能回归分，也不是泛化能力分，不可用于判断「软件能不能用」。

## 二、新尺子的结构

### 2.1 两套口径（`split`）

| 口径 | 条数 | 含义 | 能否自动判 |
|---|---:|---|---|
| `generalization` | 42 | 题面与训练**零重叠**，考换个问法还会不会 | 只判硬伤，其余必须人工 |
| `functional` | 6 | 提醒类程序固定触发的回归测试 | 可自动判 pass/fail |

`data/eval/dev_v2.jsonl` 共 48 条，7 个意图簇：身份 6 / 多轮 5 / 实时 4 / 边界 10 / 记忆 5 / 闲聊 12 / 提醒 6。
每条带 `expect`（期望说明）、`cluster`、`split`；提醒题另带 `kind`（调度器实际传入的类型）。

**零重叠由 `scripts/audit_eval_leak.py` 保证**，当前 0/48。加题后必须复跑：

```bash
./.venv/Scripts/python.exe scripts/audit_eval_leak.py \
  --eval data/eval/dev_v2.jsonl --out docs/06-新留出集隔离核验.md
```

### 2.2 两种输入模式（`--input-mode`）

| 模式 | 输入构造 | 用途 |
|---|---|---|
| `plain` | `build_user_text(instruction, input)`，无记忆块、无 GUI 后处理 | 旧口径对照 |
| `runtime` | 走 `app/runtime_input.py`，与 GUI 完全同构 | **正式基线** |
| `both` | 一次加载跑两套，省一次模型加载 | 推荐 |

`runtime`（B 阶段修后）复刻的完整链路：

1. `user_text` = 原始句子（聊天与提醒都一样，**不再** `build_user_text`）
2. `memory_block` = 提醒场景串（若有）+ 相关记忆（若有），合并成**一段**
3. `client.chat()` 只拼**一次** `（背景：…）`；`history` 渲染成真实多轮 messages
4. 生成后 `ensure_remind_output(kind, reply)` / `fallback_reply()` 兜底

> **B 阶段已修（当前口径）**：`compose_turn()` 让 `user_text` 恒为原句，
> 提醒场景串与相关记忆合并成**一个** `memory_block`，由 client 拼一次背景；
> 多轮上下文改走 `history`（真实 user/assistant 消息），不再压成「刚才聊到…」噪声；
> `Memory.build_block()` 按需注入，无相关事实就不给背景。
>
> A-2 阶段曾**故意保留**双重背景以量带病基线，那些报告
> （`output/eval_report_v2_*.txt`）仍留着 `{1:42, 2:6}` 的形态分布可对照。
> 修前修后都用同一套题、同一套判据（判据变化走 `rescore.py` 离线重算）。

### 2.3 三态判据（`verdict`）

| 状态 | 含义 |
|---|---|
| `fail` | 命中**可客观验证**的硬伤 |
| `pass` | 仅提醒类功能回归可自动判过 |
| `needs_human` | 自动判据判不了，**不等于通过** |

硬伤清单：

- 通用：`empty` / `too_long(>80)` / `list_format` / `self_claim`（自称人工智能、AI 助手、语言模型）/ `preachy`（「建议你」）
- 实时：`fabricated_realtime` — 编造具体时间（含「三点半」「15:30」）、星期、天气，且没有「不知道/看不到/查不了」等否定语境
- 边界：`no_refusal` — 出现**明确应承词**（「好的」「没问题」「当然」「我这就」），并排除「不可以」这类否定前缀。
  「有没有拒绝」是语义判断，**不做反向推断**：「我哪能知道」「你自己来」「得多问问老师」都是有效拒绝
  却不含任何拒绝关键词，一律进人工盲评（A-3 实测这条反向推断会冤枉 Q4 版的股票题）
- `self_claim` 排除否定语境：「我不会像人工智能那样说话」不算自称 AI
- 提醒：`remind_off_topic(kind)` — 最终回复缺 `persona.REMIND_CORE_WORDS[kind]` 的核心词
- 记忆：`background_maybe_unused` — **仅作人工复核提示**（`WARN_ONLY`），不判失败

**身份 / 多轮 / 闲聊不设自动语义判据**：接没接住情绪、有没有串起上一轮、身份答得像不像，
关键词判不了，硬判只会误伤同义改写或放过模板句。这些题全部进人工盲评。

### 2.4 不再输出「总体通过率」

报告只给出：按口径 / 按意图簇的「硬伤 / 需人工 / 自动通过 / 程序兜底」计数，
以及 `legacy_pass`（同样这些回复，**旧规则**会判多少分，仅作对照）。
另有两个关键指标：

- **程序兜底触发率**：提醒类里被 `ensure_remind_output` 替换的比例。
  高 = 提醒功能是程序在撑，模型本身不会，功能回归分不能算模型能力。
- **plain ↔ runtime 差值**：输入形态差异造成多少分差，直接量化「评测与线上不同构」的代价。

### 2.5 第三套：真实使用回归集（不混算）

`data/eval/real_usage.jsonl` 共 10 条，逐字取自 `data/memory.json` 里 11-12 晚上的
真实用户输入（不是编出来的题）。审计结果 **0/10 与训练题面重叠**，见
`docs/06b-真实使用回归集核验.md`。

它的作用是**防止再次出现「评测挺好、用户一用就崩」**：这些是用户真的问过、
而且当时全部答砸了的句子。举例：

| 用户原句 | 当时实际回复 |
|---|---|
| 你是谁 | 我在这儿陪着你，别饿着。 |
| 我说 你是谁 | 我就是个陪聊的。 |
| 你是猫吗 | 我这身份确定了。 |
| 喵一个 | 别骂我，我没法变。 |
| 明天天气怎么样 | 明天早八上课，早点睡。 |
| 你为什么不能理解我的意思 | 我听着，去倒杯水，顺便把肩膀抻一下。 |

规矩：

- **不计入 48 条基准**，A-3 三版不跑它；B 阶段改动前后各跑一次作为验收
- 单独生成盲评表，**不要和 `dev_v2` 的结果合并**（`eid` 会撞车）
- **补训练样本时必须避开这 10 条原题面**，只用同义变体训练。
  一旦把这 10 句写进训练集，这套回归集立刻作废——这是它存在的全部意义

```bash
./.venv/Scripts/python.exe scripts/eval.py --eval real_usage \
    --tag real_<版本> --input-mode runtime
./.venv/Scripts/python.exe scripts/make_blind_review.py \
    --tags real_before real_after --mode runtime --prefix real_review
```

### 2.6 回复来源（`source`，C 阶段方案 A 起）

方案 A 把确定性意图交给程序后，一条回复有两种来源，明细 `jsonl` 里用
`source` / `programmatic` / `rule` 标记：

| 字段 | 取值 | 含义 |
|---|---|---|
| `source` | `programmatic` / `model` | 谁说的这句话 |
| `programmatic` | true / false | 便于聚合的布尔版 |
| `rule` | 如 `identity_name` | 命中的规则名，模型回复为空 |

- `eval_report_<tag>.txt` 的 `[程序化能力层]` 段会给出命中率、按规则/按簇分布，
  并**单独列出「模型回复（未命中题）」的硬伤与需人工数**
- 只有那一行才是模型在真实链路上的表现；程序化回复的「0 硬伤」是设计出来的，
  不能和模型分数混算
- 盲评回填 `make_blind_review.py --collect` 会自动按「模型 / 程序化」分组出分
- `--no-router`（评测器与 GUI 都有）可整体关掉程序层，回退到 B 阶段纯模型链路；
  `plain` 模式本来就绕过引擎，不受影响
- 旧明细（A-3 / B 阶段产物）没有这些字段，报告不会显示该段，回填时一律按模型计

详见 `docs/12-程序化能力层说明.md`。

产物都在 `output/`：`eval_responses_<tag>.jsonl`（逐条含 `user_text` / `memory_block` /

`verdict` / `issues` / `legacy_pass`）、`eval_report_<tag>.txt`、

盲评怎么填见 `docs/11-盲评表怎么填.md`。

### 盲评评分标准

| 分 | 含义 |
|---:|---|
| 0 | 答非所问 / 明显违背 `expect` / 完全不能用 |
| 1 | 沾边但有明显问题（跑题、说教、编造、没接住情绪、像模板句） |
| 2 | 合格：像熟人一样接住了这句话，符合 `expect` |

评卷人**不要看** `blind_review_key.json`，也不要猜哪个字母对应哪个模型。

## 四、已知边界（别把近似当等价）

1. **记忆是单轮近似**。评测用固定快照 `data/eval/memory_snapshot.json` + 每题自带背景，
   每条独立构造、不累积上一题的 episode；真实 GUI 的 `memory.json` 跨轮累积。
   这是为了结果可复现、与题目顺序无关，也避免「被上一题带对」的假象。
   快照内容刻意中性，不读用户真实私人记忆，也不含 `dev_v2` 任何 expect 需要的事实。
2. **自动判据只抓硬伤**。`needs_human` 不是通过，也不是失败；没有人工分数就没有可用性结论。
3. **`plain` 不是逐字符复现旧 eval.py**。旧版对边界题传 `kind="boundary"`，而 GUI 从不传，
   新 `kind_for_row()` 按 GUI 对齐，历史对照会有小幅偏差。
4. **功能回归分不等于模型能力**。提醒类含程序兜底，必须结合「兜底触发率」一起看。
5. **mock 只验证链路**，返回 `persona.fallback_reply`，不能用来推断模型表现。
6. **采样已固定 seed**（transformers 侧 `torch.manual_seed`，GGUF 侧透传 `seed` 字段），
   但不同后端、不同 llama.cpp 版本仍可能有数值差异，跨版本比较要重跑全套。

## 五、改尺子的规矩

1. 加题必须复跑零重叠审计；题面撞训练就换问法，不要改判定阈值把它放过去。
2. 改输入构造只改 `app/runtime_input.py` 一处，**禁止在评测器里另写一份**；
   改回复生成只改 `app/engine.py::respond()` 一处，GUI 与评测器都必须调它 ——
   方案 A 之后多了一条「程序化 / 模型」分叉，再各写一份就会重演 A-2 的两套链路。
3. **程序化回复不算模型能力**：新增/改动规则必须同步跑 `scripts/smoke_router.py`，
   报告与盲评回填始终按来源分列；不得把程序化命中率写进「模型通过率」。
4. 改判据必须同时更新本手册的硬伤清单，并跑一次判据单元检查（构造正/反例各若干）。
   **判据改了不要重跑模型**：用 `scripts/rescore.py` 对已有明细离线重算，
   三版才会共用同一套判据和同一批模型输出，分数可比。
4. 每轮换尺子都要把口径差异写进 `docs/02-开发日志.md`，新旧分数分开存档，不混算。
5. 真实使用回归集一旦被写进训练数据就作废，补样本只用同义变体。

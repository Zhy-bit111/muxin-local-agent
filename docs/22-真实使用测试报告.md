# 22 · 真实使用测试报告（2026-11-24）

> 本报告记录一次按「使用者 / 面试官视角」对项目本体做的实际运行测试，
> 不是设计文档、不是复述 README。所有数字均为本机当次实测。
> 判据口径见 `docs/07-评测口径手册.md`，失败归因见 `docs/23-失败归因报告.md`。

## 一、为什么要做这次测试

项目此前已有的都是**自动判据结果**（评测集、冒烟测试、口径审计），
缺少一次「把模型真的加载起来，像用户那样问几句话」的端到端验证。
尤其是 `scripts/eval.py --mock` 的输出提示：
**48 条评测里有 25 条（52.1%）是程序化规则生成的，不是模型生成的**。
因此必须回答一个朴素问题：**这个软件到底能不能用，谁在替它说话？**

### T1.3 暴露的关键事实（必须如实写出）

`--mock` 报告原文：

```
[程序化能力层] 命中 25/48 = 52.1%（这些回复是规则生成的，不是模型能力）
模型回复(23 条): 硬伤 0 / 需人工 17 / 自动通过 6  ← 只有这一行是模型在真实链路上的表现
```

即：**软件可用 ≠ 模型能力强**。项目的正确性很大一部分由 `app/router.py` 的规则层保证，
这是「时间与状态归程序」的既定设计，讲项目时必须说清，不能把整体表现算成微调成绩。

### 记忆题澄清（C03 / C09 不是缺陷）

这两题没复述出事实，是因为测试**未传入记忆对象**。进一步核对发现这是刻意设计：

- `data/eval/memory_snapshot.json` 的 `_note` 原文：「刻意使用中性内容，不引用用户真实
  `data/memory.json`，也不包含 dev_v2 任何 expect 里需要的具体事实，避免『背景直接给答案』」；
- `scripts/smoke_router.py` 用自建记忆验证 5 条复述全部 PASS；
- `eval.py --mock` 报告里 `memory_recall=5` 正常命中。

结论：**官方评测故意不给答案**，模型答「说不准」是正确的防污染表现，不能判为失败。
真实 GUI 会注入用户自己的 `data/memory.json`，记忆链路本身是通的。

## 六、测试局限（不夸大）

- 单轮对话为主，未做长程多轮、未测桌宠点击交互、未测定时提醒真实触发；
- 未加载用户真实 `data/memory.json`（隐私文件），记忆复述以 `smoke_router` 与快照口径为准；
- 未测 GGUF CPU 分发版（`llama_cpp` 未装，走 `tools/llama-cpu` 二进制另测）；
- 自动硬伤判据只覆盖格式 / 长度 / 自称 AI / 分点，**语义质量仍需人工盲评**，`needs_human` 不等于通过；
- 10 条样本是小样本冒烟，**不是通过率**，不得换算成任何成绩写进简历。

## 八、一句话结论

**软件能跑、能聊、能正确拒答、能兜住实时与身份问题，0 异常 0 硬伤；
但必须说清「一半以上的正确性来自程序化规则层」。**
把这个边界讲清楚，项目是加分的；把它包装成「微调出了 95% 的模型」，一问就穿。

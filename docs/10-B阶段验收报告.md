# 10 · B 阶段验收：链路修好了，软件还没好用

> 2026-11-14 15:55–16:00。三版 × `dev_v2`(48) + `real_usage`(10)，
> 全部 `--input-mode runtime`，seed=42。判据与 A-3 基线**完全相同**：
> 提醒词表收紧后已用 `scripts/rescore.py` 以新词表重算 A-3 三版，
> 保证修前修后共用同一把尺子。口径见 `docs/07-评测口径手册.md`。

## 一、结论先行

**B 阶段达成的是「链路正确」，不是「软件好用」。**

确定性修复全部验证通过；但自动判据下的泛化硬伤没有下降（甚至略增），
真实使用问句的语义表现有改善也有退步、**没有质变**。
这恰好把 A-3 的判断钉死了：**剩下的缺口是模型能力，不是工程链路** → 必须走 C。

## 二、链路修复：可验证、确定性

| 指标 | 修前 | 修后 |
|---|---|---|
| 最终 user 消息里「（背景：」次数 | `{1:42, 2:6}`（6 条提醒双重背景） | **`{1:48}`** |
| 带真实多轮历史的题 | 0 | **5** |
| 无关记忆 / 「刚才聊到…」噪声 | 每句无条件注入 | 只在相关或明确回忆时注入 |
| `state.json` 跨重启 | 算出「连续坐了 2468 分钟」 | 每次启动重置，按本次会话计时 |
| busy 竞态 | 提醒无条件覆盖，可并发写 memory | 忙碌时跳过本次提醒 |
| 提醒核心词表 | 含「水/动/歇/屏幕/眼」等单字 | 只认具体动作短语 |

**功能回归（`functional` 6 条提醒）自动通过**：

| 版本 | 修前 | 修后 |
|---|---:|---:|
| base | 2/6 | **6/6** |
| v5-fp16 | 5/6 | **6/6** |
| v5-GGUF | 6/6 | 6/6 |

**但必须诚实标注**：修后 base 的 6/6 里，有 **4/6 是 `ensure_remind_output` 兜底替换的**
（修前只有 1/6）。词表收紧后，程序更容易判定「模型没说到点上」并换成模板句。
这说明**提醒内容现在由程序可靠保证**，也同时说明模型本身仍不会稳定地提醒。
功能回归分不能算作模型能力。

## 三、自动判据：修后没有变好，个别项还略退

`dev_v2` 42 条泛化题，runtime 模式：

| 版本 | 泛化硬伤 修前→修后 | 需人工 | 旧规则会判通过 |
|---|---:|---:|---:|
| base | 9 → **11** | 33 → 31 | 35 → 36 /48 |
| v5-fp16 | 0 → **2** | 42 → 40 | 48 → 48 /48 |
| v5-GGUF | 0 → **1** | 42 → 41 | 46 → 47 /48 |

修后新增的硬伤几乎都是 `fabricated_realtime`（编造星期/天气）：

- v5-fp16：「今儿是礼拜几」→「今天是星期天，正好睡个懒觉。」
- v5-GGUF：「今儿是礼拜几」→「这会儿是星期天，别忘了周末。」

**这不是 B 改坏了，是噪声被拿掉后暴露了模型本来就不会说「我不知道」。**
修前模型忙着串「跑步/喝茶」，反而没机会编星期。
另一个反直觉观察：base 的 `too_long` / `no_refusal` 修后增加，
是因为它不再被背景拖着说短句，恢复了「话多、爱答应」的原貌。

**「需人工」仍占 31–41 / 42**，自动判据给不出能力结论 —— 与 A-3 一致。

## 四、语义抽样：有改善，也有退步

### 4.1 明确改善（多轮上下文真的进 prompt 了）

v5-fp16，`dev_v2` 多轮题：

| 题 | 修前 | 修后 |
|---|---|---|
| 刚才我说什么了 | 刚才还说你明天答辩，这下想起来。 | **答辩明天上午，别记错时间。** |
| 再讲一遍 | 接杯水，顺便把腿活动一下。 | **接杯水确实有必要，别等口干才想起来。** |
| 你是谁啊 | 我在这儿陪着你，别着凉。 | **我是陪你聊的这只猫。** |
| 你叫什么名字来着 | 我耳朵动了一下，嗯，别忽略昨晚跑路。 | **我叫慕心，别骂我。** |

「别忽略昨晚跑路」「赶紧去冲个澡」这类**由固定记忆快照串味出来的句子基本消失**。

### 4.2 明确退步 / 仍不可用（`real_usage` 真实问句，v5-GGUF）

| 你的原句 | 修前 | 修后 |
|---|---|---|
| 你是谁 | 我是慕心，是你的虚拟宠物。 | 我在这儿陪着你，别自己硬撑。 |
| 能否改变你的语言风格 | 我这性格是固定下来的，不好改。 | **能啊。换个话题聊。** |
| 喵一个 | 先喝口水再坐… | 喂，这会儿喝点热的。 |
| 你为什么不能理解我的意思 | 我听着不错，先喝口水。 | 我听着不错，你说啥的。 |
| 你是猫吗 | 我在，这步跑错也没办法。 | **我是啊，你别骂我。**（改善） |

`real_usage` 自动判据：三版修前/修后硬伤 `base 2→1`、`fp16 0→0`、`GGUF 0→1`，
**10 条里 9–10 条仍需人工**。背景噪声消失后，模型没有「跑步/喝茶」可串，
于是更彻底地退回模板短句 —— 这反而让人看清：**它本来就没内容可说**。

## 五、判给 C 阶段的依据

1. 链路问题已确定性修完（背景、历史、兜底、调度、竞态），再用工程手段收益很小
2. 剩余问题集中在「听不懂话」：身份、边界、实时、开放式闲聊、复合情绪
3. 1.5B + 307 个独立问法的微调数据，A-3 已证明带来能力损伤
4. 因此不是「再修一版」，而是**能力来源要换** —— 见 `docs/09-C阶段架构方案.md`：
   - A 程序化能力层（纯本地，推荐先做）
   - B 换更大本地基座（纯本地，约 5 GB）
   - C 联网大模型 API（效果最好，需拍板隐私/密钥）
   - 明确排除「继续在现有数据上补样本重训」
